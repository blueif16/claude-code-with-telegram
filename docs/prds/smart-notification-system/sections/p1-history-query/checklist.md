# P1 历史查询 - 验收清单

## 命令实现

- [ ] /history 命令返回最近10条记录
- [ ] /history <tool> 按工具类型过滤（bash, read, write, edit, grep）
- [ ] /history <event> 按事件类型过滤（stop, error, tool_use）
- [ ] /history <n>h 按时间范围过滤（如 1h, 24h）
- [ ] /last 返回最后一条记录的详细信息
- [ ] /last <n> 返回最近n条记录

## 持久化

- [ ] 历史记录保存到 logs/tool_history.json
- [ ] 服务器启动时自动加载历史记录
- [ ] 每次新增记录后自动保存
- [ ] 自动清理超过1000条的旧记录
- [ ] 文件格式为有效的 JSON

## 格式化输出

- [ ] 简洁模式显示：时间、事件类型、工具名称
- [ ] 详细模式显示：时间、事件、工具、输入、输出
- [ ] 输出使用 Telegram Markdown 格式
- [ ] 长文本自动截断（如输入输出超过100字符）
- [ ] 空结果返回友好提示

## 功能测试

- [ ] 执行10个工具调用，/history 返回10条
- [ ] /history bash 只返回 bash 工具记录
- [ ] /history error 只返回错误事件
- [ ] /history 1h 只返回最近1小时记录
- [ ] /last 返回最新一条的完整信息
- [ ] /last 5 返回最近5条

## 持久化测试

- [ ] 添加记录后，logs/tool_history.json 文件更新
- [ ] 重启服务器，历史记录仍然存在
- [ ] 添加1100条记录，验证只保留最近1000条
- [ ] 文件损坏时服务器仍能正常启动（降级为空历史）

## 性能测试

- [ ] 查询1000条记录响应时间 < 1秒
- [ ] 保存历史记录不阻塞主线程
- [ ] 历史文件大小合理（< 10MB）

## 错误处理

- [ ] 无效的过滤参数返回友好错误
- [ ] /last 参数非数字时返回错误
- [ ] 历史文件不存在时正常启动
- [ ] 历史文件格式错误时记录日志并重置
